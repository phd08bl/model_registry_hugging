The most efficient arrangement is to maintain **one FDE case record for each prioritised process**. The cards guide conversations, the checklists test completeness, and the templates capture the agreed outputs.

Do not ask stakeholders to complete all cards and 26 questions themselves. The FDE lead should facilitate the discussions, review evidence and populate the case record.

# Stage 1: Candidate process problem and outcome

## Purpose

Capture enough information for the FDE team to understand the candidate and prepare it for leadership prioritisation. This is not detailed discovery and does not approve a tool.

## Card 1A: Candidate Problem Card

### Completed by

The sponsoring IVT head or Grade G colleague, with light support from the FDE team.

### How to use it

Spend approximately 15–20 minutes capturing the problem. A written submission can be used, followed by a short FDE clarification call if needed.

### Template

| Question | Response |
|---|---|
| What process or workflow needs improvement? | |
| What triggers the process? | |
| What marks completion? | |
| What is the current problem? | |
| Give one recent example | |
| Who experiences the problem? | |
| Which teams are affected? | |
| What is the approximate frequency or volume? | |
| What is the risk, control or delivery impact? | |
| What outcome should improve? | |
| How would we recognise improvement? | |
| Who is the proposed process owner? | |
| Which SMEs or users could support discovery? | |
| Is the process local or potentially common across MRO? | |
| Are there existing tools, backlog items or initiatives connected to it? | |
| What evidence is currently available? | |

## Stage 1 checklist

- [ ] The candidate describes a process problem rather than only requesting a tool.
- [ ] A recent example has been provided.
- [ ] The affected users and teams are identified.
- [ ] The desired outcome is understandable.
- [ ] An initial indication of volume, frequency or impact exists.
- [ ] A proposed process owner has been identified.
- [ ] SMEs and users are potentially available.
- [ ] Existing backlog items and related initiatives have been checked.
- [ ] The candidate is not an obvious duplicate.
- [ ] There is sufficient information for leadership to compare it with other candidates.

This draws mainly on master checklist questions 1–5, 20, 22 and 26.

## Output: Candidate Brief

The FDE team converts the submission into a short brief:

> **Problem:**  
> **Evidence/example:**  
> **Desired outcome:**  
> **Affected users:**  
> **Scale/materiality:**  
> **Proposed owner:**  
> **Existing related work:**  
> **FDE recommendation:** Ready for prioritisation / clarify / combine / route elsewhere.

## Exit decision

The FDE intake lead decides whether the candidate is ready to enter the leadership pack. This does not give it priority or delivery capacity.

# Stage 3: FDE discovery

## Purpose

Understand how the process actually works, where the problem occurs, what evidence and controls are involved and what outcome should improve.

Cards 2–6 are used in this stage.

## Card 2: Process and Controls

### Participants

Process owner, methodology owner and SMEs.

### Questions

| Area | Questions |
|---|---|
| Boundary | What starts and ends the process? What is in and out of scope? |
| Purpose | What outcome is the process intended to produce? |
| Inputs | What information, evidence and approvals are required? |
| Outputs | What is produced, recorded, communicated or approved? |
| Steps | What are the main activities and decision points? |
| Criteria | What policies, methodology or professional judgement are applied? |
| Controls | What prevents, detects or corrects errors? |
| Exceptions | What happens when information is incomplete or conflicting? |

### Output

- Process boundary.
- Intended outcome.
- Main control requirements.
- Methodology and judgement points.

## Stage 5 checklist

- [ ] The experiment answers a specific question.
- [ ] It tests the most material uncertainty.
- [ ] Representative cases are available.
- [ ] Test data is authorised.
- [ ] Baseline and acceptance thresholds are defined in advance.
- [ ] Human reviewers and approvers are named.
- [ ] The experiment does not perform unauthorised production actions.
- [ ] Failure and escalation procedures are defined.
- [ ] Outputs and evidence will be retained.
- [ ] Limitations and untested assumptions will be recorded.
- [ ] Time, SME support and technical capacity are committed.

## How to use it

The FDE lead owns the experiment charter. Developers implement the smallest viable slice. Users perform realistic tasks. The process owner confirms whether the test cases represent the process.

Avoid adding desirable features that do not help answer the experiment question.

## Exit authority

The experiment produces evidence but does not approve production delivery. It moves to Stage 6 for evaluation.

# Recommended storage and workflow

Use a single Confluence hierarchy:

```text
MRO FDE Portfolio
├── Candidate Backlog
├── Active FDE Cases
│   └── FDE-XXX Process Name
│       ├── Case record and decision log
│       ├── Discovery evidence
│       ├── Experiment evidence
│       ├── Delivery and handover
│       └── Benefits review
├── Reusable Patterns and Components
└── Closed Cases
```

Each case should have one Jira epic using these lifecycle statuses:

```text
Candidate
→ Prioritised
→ Discovery
→ Route Assessment
→ Experiment
→ Evaluation
→ Delivery
→ Controlled Rollout
→ Benefits Review
→ Closed
```

Technical stories belong beneath the epic only after the route and experiment are sufficiently defined.

# Proportionate use of the toolkit

| Case route | Required materials |
|---|---|
| Light | Candidate Card, Leadership Decision, relevant parts of Cards 2/4/7, short action plan and process-owner acceptance |
| Standard | All relevant discovery cards, options assessment, experiment charter, evaluation record, delivery/handover and benefits review |
| Enhanced | Full toolkit, architecture and data review, formal methodology control, independent challenge, controlled rollout and detailed monitoring |

The practical discipline is:

> **Use cards to ask, evidence to verify, templates to record, checklists to challenge and gates to decide.**

This keeps the FDE process evidence-led without turning it into a documentation exercise.
