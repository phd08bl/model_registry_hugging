The “agent” is not making the risk decision. It is managing the Case and deciding what permitted preparation work should happen next.

A useful way to describe it is:

> The Coordinator is an intelligent case manager operating inside deterministic governance boundaries.

### What the Coordinator actually does

For each Case, it repeatedly:

1. Reads the authoritative Case state.
2. Identifies unresolved evidence objectives.
3. Asks the deterministic `PolicySupervisor` what actions and tools are permitted.
4. Selects the next action:

   - directly, when only one deterministic action is appropriate;
   - through the bounded LLM router, when several approved evidence actions are possible.

5. Invokes the selected tool through the approved registry.
6. Verifies the result before accepting it.
7. Updates the Case state.
8. Invalidates stale dependent results when information changes.
9. Decides whether to continue, stop safely or pause at an AIRO Gate.
10. Preserves the complete action and decision history.

### What is genuinely agentic

It does not always execute the same steps in the same order.

Depending on the Case, it can:

- select a RAG evidence check;
- select a supplier evidence check;
- select an agentic-AI autonomy check;
- bypass the LLM when only one action is permitted;
- stop when verification fails;
- request additional evidence;
- replan after evidence changes;
- rerun only affected work;
- skip a Gate when deterministic policy permits;
- escalate when confidence, evidence or authority is insufficient.

Its freedom is deliberately limited. The agent cannot invent tools, exceed budgets or select risk outcomes.

### What remains deterministic

The LLM does not control:

- materiality scoring or band;
- 2LoD engagement;
- autonomy profile assignment;
- whether a mandatory Gate can be skipped;
- final approval;
- publication authority.

Materiality and 2LoD engines produce proposals. AIRO owns the final judgement.

### Why this is better than manually moving through tabs

Tabs are presentation. They show information, but they do not reliably govern what must happen next.

| Manual tab workflow | Case Coordinator |
|---|---|
| User decides which tab or check to run next | Coordinator determines the next permitted action from Case state |
| Easy to overlook a required check | Supervisor enforces mandatory checks |
| User may follow steps in the wrong order | StateGraph controls ordering and branching |
| Evidence changes may leave old results visible | Dependencies are invalidated and superseded |
| Every Case follows roughly the same route | Route adapts to evidence, risk, profile and exceptions |
| Tool results may be accepted without consistent checks | Every governed result passes through verification |
| Users must remember when human approval is required | Mandatory AIRO Gates interrupt automatically |
| Audit history depends on manual recording | Actions, tools, results, verification and decisions are traced |
| Restarting may lose the user’s position | SQLite checkpoints restore the pending Gate |
| Automation permissions may be informal | Profile permissions are assigned and enforced by policy |

### Concrete example

Suppose the questionnaire says `personal_data=false`, but submitted evidence mentions employee names and email addresses.

The Coordinator:

1. Extracts the submitted evidence.
2. Runs the deterministic consistency checker.
3. Selects relevant RAG and supplier checks.
4. Verifies citations and tool outputs.
5. Records the conflict separately from advisory observations.
6. Pauses at Gate 1.
7. Receives corrected evidence and `{"personal_data": true}` from AIRO.
8. Invalidates the previous evidence result.
9. Reruns the relevant evidence work.
10. Pauses at Gate 2 for confirmation.
11. Runs deterministic materiality and 2LoD engines.
12. Moves through challenge, final decision and publication Gates.

With manual tabs, the user would need to remember which results had become stale, which checks must be rerun and which decisions require AIRO approval.

### Is an agent always better?

No. A fixed workflow is preferable when:

- every Case follows exactly the same route;
- inputs are fully structured;
- there are no evidence loops;
- no dynamic tool selection is needed;
- changes have simple dependencies.

The Coordinator is useful because AI risk cases are often incomplete, inconsistent and variable. The design therefore uses a hybrid:

> A deterministic governance spine, bounded agentic evidence preparation and mandatory human judgement.

The tabs are still useful, but they are now views into the Case. They no longer control the workflow.
